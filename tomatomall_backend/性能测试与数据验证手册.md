## 1. 库存精准扣减测试（超卖 + QPS）

### 1.1 对应简历描述
> "高并发下乐观锁版本冲突导致库存扣不完，改换数据库原子行锁，配合预冻结+异步扣减+超时回滚模型，QPS从2000降至1000以换取业务正确执行，实现零超卖"

### 1.2 实际实现核对
- **原子行锁**：[StockpileRepository.decreaseStock](src/main/java/com/example/tomatomall/Repository/StockpileRepository.java#L13-L16) 用单条 `UPDATE ... WHERE amount >= quantity` 原子扣减。
- **预冻结**：扣减时 `amount -= q, frozen += q`，下单未支付即冻结。
- **异步扣减**：支付后由 [OrderCreatedConsumer.processOrderPayment](src/main/java/com/example/tomatomall/kafka/OrderCreatedConsumer.java#L121-L168) 异步把 frozen 减掉。
- **超时回滚**：[OrdersServiceImpl.cancelPendingOrder](src/main/java/com/example/tomatomall/service/serviceImpl/OrdersServiceImpl.java#L63-L101) 取消时把 frozen 还回 amount。（注：AlipayUtils 里 30 分钟自动取消已注释，目前需手动调用 cancel。）

### 1.3 测试 A：零超卖验证

**目标**：库存 = 10，并发 100 个下单请求，验证成功订单数 ≤ 10，最终库存 + frozen = 10。

**步骤**：

```python
# oversell_test.py  —— 零超卖验证脚本
import requests, threading, time

BASE = "http://localhost:8080"
TOKEN = "替换为真实token"   # 见 0.4
PRODUCT_ID = 1
THREADS = 100

headers = {"token": TOKEN}
results = {"success": 0, "fail": 0, "errors": []}
lock = threading.Lock()

def worker():
    try:
        # 1. 加入购物车
        r = requests.post(f"{BASE}/api/cart",
                          params={"productId": PRODUCT_ID, "quantity": 1},
                          headers=headers, timeout=10)
        if r.status_code != 200:
            with lock:
                results["fail"] += 1
            return
        cart_id = r.json()["data"]["cartItemId"]
        # 2. 立即结算
        r2 = requests.post(f"{BASE}/api/cart/checkout",
                           params={"cartItemId": cart_id,
                                   "shoppingAddress": "test",
                                   "paymentMethod": "ALIPAY"},
                           headers=headers, timeout=10)
        with lock:
            if r2.status_code == 200:
                results["success"] += 1
            else:
                results["fail"] += 1
                if len(results["errors"]) < 3:
                    results["errors"].append(r2.text[:200])
    except Exception as e:
        with lock:
            results["fail"] += 1
            if len(results["errors"]) < 3:
                results["errors"].append(str(e))

t0 = time.time()
ts = [threading.Thread(target=worker) for _ in range(THREADS)]
for t in ts: t.start()
for t in ts: t.join()
dt = time.time() - t0

print(f"并发数: {THREADS}")
print(f"成功下单: {results['success']}")
print(f"失败(含库存不足): {results['fail']}")
print(f"总耗时: {dt:.2f}s")
print(f"QPS: {THREADS/dt:.1f}")
print(f"错误样本: {results['errors']}")
```

### 1.5 关于"QPS 从 2000 降至 1000"的说明

当前代码只保留了**原子行锁**版本，没有乐观锁版本可对比。有两种处理方式：

- **方式 A（推荐，诚实表述）**：只报告原子行锁的真实 QPS，简历改为"采用数据库原子行锁，QPS ≈ XXX，实现零超卖"。
- **方式 B（要对比数据）**：临时实现一个乐观锁版本做对照。在 `Stockpile` 实体加 `@Version` 字段，`decreaseStock` 改为先读后 CAS 更新，同样压测记录 QPS，再换回原子行锁版本。

如果选方式 B，参考实现：
```java
// Stockpile 实体加字段
@Version
private Integer version;

// Repository 加乐观锁方法
@Modifying
@Query("UPDATE Stockpile s SET s.amount = s.amount - :q, s.frozen = s.frozen + :q, s.version = s.version + 1 " +
       "WHERE s.id = :id AND s.amount >= :q AND s.version = :v")
int decreaseStockOptimistic(@Param("id") Integer id, @Param("q") Integer q, @Param("v") Integer v);
```

> 乐观锁在高并发下会出现大量 `OptimisticLockingFailureException` 重试，QPS 通常高于原子行锁但会有扣减失败，这正是"换取正确性"的对照点。

```python
import requests, time, statistics

BASE = "http://localhost:8080"
PID = 1
URL = f"{BASE}/api/products/{PID}"

def measure(n=50):
    ts = []
    for _ in range(n):
        t0 = time.perf_counter()
        r = requests.get(URL, timeout=10)
        t1 = time.perf_counter()
        ts.append((t1 - t0) * 1000)  # ms

print("=== 接下来 50 次（应命中 L1 Caffeine）===")

print(f"  中位数: {statistics.median(warm_l1):.1f} ms")
print(f"  P95: {sorted(warm_l1)[int(len(warm_l1)*0.95)]:.1f} ms")
```

### 2.4 测试 B：数据库 QPS 降低比例（对应"降低70%"）

```powershell
# 清空 Redis 商品缓存（注意：不要重启服务，否则 Caffeine 也清空但 Redis 还在；
```

3. **场景二：有缓存**——不清缓存，再请求 100 次（此时 L1 Caffeine 全命中）：

> 若场景一 100 次请求只查库 1 次（其余命中 L1/L2），则"每请求平均查库次数"= 1/100 = 0.01 次，对比无缓存时每次都查库（100 次），降低 99%。

```python
# full_benchmark.py  —— 综合压测
import requests, threading, time, statistics, json

BASE = "http://localhost:8080"

def login(u, p):
    r = requests.post(f"{BASE}/api/accounts/login", json={"username":u,"password":p})
    return r.json()["data"]

TOKEN = login("tester", "123456")
H = {"token": TOKEN}

def stress(name, fn, n=500, ramp=10):
    results = {"ok":0,"fail":0,"ts":[]}
    lock = threading.Lock()
    sem = threading.Semaphore(1)
    def worker():
        sem.acquire(); sem.release()
        t0=time.perf_counter()
        try:
            ok = fn()
            dt=(time.perf_counter()-t0)*1000
            with lock:
                results["ts"].append(dt)
                results["ok" if ok else "fail"] += 1
        except:
            with lock: results["fail"] += 1
    ts=[threading.Thread(target=worker) for _ in range(n)]
    # 简单 ramp-up
    batch = max(1, n//ramp)
    for i in range(0, n, batch):
        for t in ts[i:i+batch]: t.start()
        time.sleep(1)
    for t in ts: t.join()
    ts2=results["ts"]
    print(f"\n=== {name} (并发 {n}) ===")
    print(f"成功: {results['ok']}  失败: {results['fail']}  成功率: {results['ok']/n*100:.2f}%")
    if ts2:
        print(f"QPS: {n/(sum(ts2)/1000):.1f}  平均: {statistics.mean(ts2):.1f}ms  P95: {sorted(ts2)[int(len(ts2)*0.95)]:.1f}ms  P99: {sorted(ts2)[int(len(ts2)*0.99)]:.1f}ms")

def get_product():

stress("商品查询(多级缓存)", get_product, n=500, ramp=10)

def add_cart():

stress("加购物车(鉴权)", add_cart, n=500, ramp=10)
```

## 9. 据实改写简历的建议

测得真实数据后，按以下原则改写：

1. **数字据实替换**：把所有 `____` 替换为真实测得值。
2. **没有对比数据的，改为单值表述**：
   - 例如只测了原子行锁 QPS = 800，没有乐观锁对比，则改为"采用数据库原子行锁，QPS ≈ 800，实现零超卖"。
3. **测试条件要可说明**：面试官可能问"500 并发是在什么机器上测的"，准备好回答（本地笔记本 / CPU / 内存 / JDK 版本 / 是否容器化）。
4. **保留技术栈描述真实**：Spring Boot / JPA / Kafka / Redis(Redisson) / Caffeine / 支付宝 SDK / JMeter / Docker 均已在代码中真实使用，可放心写。
5. **薄弱点诚实处理**：
   - "超时回滚"目前需手动调 cancel，自动 30 分钟超时已注释——若面试问到，说明"已实现取消回滚逻辑，自动超时定时任务为 TODO"。
   - "下单耗时缩短 60%"在 localhost 环境差异可能很小——可改为"通过 Kafka 异步解耦，下单主链路耗时缩短至 ____ ms"。
